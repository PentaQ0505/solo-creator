# Automation and continuity

## Separate method from schedule

Use this skill to define and execute the editorial method. Create or update a scheduled task only when the user explicitly asks for recurring or future execution. Test the manual workflow first when its outputs have not yet been reviewed.

## Recommended recurring workflows

Offer these only when they match the user's request:

### Weekly topic desk

- Review the persistent content bank and recent supplied materials.
- Research only current topics relevant to the creator profile.
- Produce 8–12 candidates, rank the top three, and prepare a sustainable two-post Xiaohongshu plan.
- Avoid repeating recently published promises.

### Biweekly WeChat desk

- Select the strongest recent topic or source cluster.
- Build one long-form article from complete evidence and reasoning.
- Prefer durable value over a weak weekly deadline.

### Weekly performance review

- Use only metrics the user supplies or an explicitly connected source can read.
- Compare content types over time; do not over-interpret one post.
- Propose the next three experiments and update the content bank.

## Persistent content bank

When a persistent project or user file is available, maintain one canonical content bank rather than scattering entries across outputs. Search for the existing bank before creating a new one. Suggested sections:

- Inbox
- Ready to develop
- Drafted
- Published
- High-performing patterns
- Exhausted or rejected

Record source dates, evidence, usage history, and remaining derivatives. Never store secrets or private user data without a clear need.

## Publishing boundary

- Default to preparing drafts for manual approval.
- Do not schedule, upload, or publish content merely because a recurring plan exists.
- If direct platform action is requested, present or obtain approval for the final content and exact target first.
- If the platform is unavailable, return a complete copy-ready package rather than claiming publication.
